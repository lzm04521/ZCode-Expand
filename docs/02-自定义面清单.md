# ZCode 可自定义面清单

按"改动代价"从低到高排列。**优先用上面的层级**——越靠上，升级越不会丢。

安装目录记为 `%LOCALAPPDATA%\Programs\ZCode`（本机 `C:\Users\lzm04\AppData\Local\Programs\ZCode`）。

## A. 官方扩展面（零维护成本，首选）

| 面 | 位置 | 能做什么 |
|---|---|---|
| 全局指令 | `~/.zcode/AGENTS.md` | 所有会话生效的工作规则 |
| 子智能体 | `~/.zcode/agents/*.md` | 自定义 agent（模型、工具、标题） |
| 斜杠命令 | `~/.zcode/commands/` | 自定义 `/命令` |
| Skills | `~/.zcode/skills/`、项目内 `.zcode/skills/` | 能力包（含 references 底库） |
| 插件 | 插件市场、`~/.zcode/cli/plugins/`、`~/.zcode/plugin-workspace/` | 打包分发 skills/命令/agent/hook/MCP |
| MCP | `~/.zcode/cli/config.json` 的 `mcp` 节点 | 接入外部工具服务 |
| Hooks | `~/.zcode/cli/config.json` 的 `hooks` 节点 | 工具调用前后拦截 |
| 项目级 | 项目内 `CLAUDE.md` / `AGENTS.md` / `.zcode/` | 单项目覆盖 |

优先在这里解决。**改不了 UI 和内置行为**，但能覆盖大部分"加能力"的需求。

## B. 用户数据区（不动安装包，升级不丢）

根目录 `~/.zcode/`：

| 路径 | 内容 | 备注 |
|---|---|---|
| `v2/config.json` | 桌面端 provider 与按模型配置（含 API key、模型上下文、`reasoning` 思考档位） | **点 2 的落点**，schema 带 `.passthrough()`，加字段安全 |
| `v2/setting.json` | 桌面端设置（`recentProjects`、`locale`、窗口、各种开关） | schema 是严格 zod，自定义字段会被剥离，需改包内 schema |
| `v2/credentials.json` | 凭据 | **不要手改** |
| `v2/tasks-index.sqlite` | 任务索引（含 WAL） | 不要手改 |
| `cli/config.json` | CLI 侧配置：`skills` / `mcp` / `hooks` / `plugins` / `command` | 修改后需重启会话 |
| `cli/plugins/` | 插件市场缓存、marketplaces | — |
| `AGENTS.md`、`agents/`、`commands/`、`skills/` | 见 A 节 | — |

## C. 安装包内、asar 外（可直接改文件，无需重打包）

| 路径 | 内容 | 价值 |
|---|---|---|
| `resources/model-providers/models_catalog_*.json` | 142KB，10 家模型供应商目录：模型 id、上下文窗口、多模态、`reasoning` 档位与默认档 | **点 2 的另一个落点**，可直接给内置供应商改默认思考档位 |
| `resources/config/default.json` | 反馈表单地址、社区链接 | 低价值 |
| `resources/glm/packages/*` | 8 个内置插件包：`android-emulator-plugin`、`browser-use-plugin`、`document-skills-plugin`、`ios-simulator-plugin`、`restore-legacy-sessions-plugin`、`skill-creator-plugin`、`zcode-cua-plugin`、`zcode-guide-plugin`。每个含 `.zcode-plugin`、`skills/`、`commands/`、`hooks/`、`dist/` | 可直接改内置插件的行为/文案 |
| `resources/glm/zcode.cjs` | 插件加载入口 | 慎改 |
| `resources/tools/cua-helper/` | CUA 辅助进程（含自带 node_modules） | 慎改 |
| `resources/app-update.yml` | 更新源（本机 provider `generic`、url `http://localhost:8081`） | 影响是否会被自动更新覆盖 |
| `resources/app.asar.unpacked/` | node-pty、ssh2 原生模块 | 本仓库不支持替换此区条目 |

这一层的特点是**升级时会被安装包整体覆盖**，所以改动要留副本并纳入版本管理。

## D. 安装包内、asar 里（必须重打包，本仓库补丁集管理）

| 路径 | 说明 |
|---|---|
| `out/renderer/index.html` | 渲染层入口，**注入点** |
| `out/renderer/assets/*.js` | 渲染层。主包 `styles-DyAcaLKy.js`（4.65MB，几乎所有 UI 都在里面）、i18n `IntlProvider-*.js`（5057 个文案键）、共享 schema `src-*.js` |
| `out/main/index.js` + `out/main/chunk-*.js` | 主进程（窗口、设置服务、更新） |
| `out/host/index.js` + `out/host/chunk-*.js` | host 进程（模型调用、provider 解析、reasoning 注入） |
| `out/scheduler/index.js` | 调度进程 |
| `out/preload/*.cjs` | preload 桥（`window.zcode` 在这里定义） |
| `out/metadata/build-meta.json` | 版本元数据，只读参考 |

**注意**：`chunk-*.js` 与 `assets/*.js` 的文件名带内容哈希，**每次官方构建都会变**。跨版本适配时第一步就是重新定位文件名。

## E. 关键运行时事实（改动前必读）

- **preload 没有暴露设置读写**。`window.zcode` 只有 `syncAppSettings`（渲染层→主进程推送）和 `onSettingsChanged`（主进程→渲染层通知），没有 `getSetting/updateSetting`。所以涉及设置的读写**必须留在包内补丁里**，外置模块只能通过包内暴露的全局契约间接使用。
- 设置写入链路：渲染层 `nx()` hook（返回 `{settings, loading, error, update, refresh}`）→ `settingService.update(patch)` → 主进程 `Kl.parse(归一化后的 patch)` + `Gr.parse({...当前, ...patch})` → 整体回写 `setting.json`。
- 设置 schema 有三份同构副本（main / host / renderer），改字段要三份一起改。
- 渲染层 UI 的文案走 i18n（5057 个键），直接写中文字面量在菜单项里是可行的（本项目就这么做），但不能走 `formatMessage`。
