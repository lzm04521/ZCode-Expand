# 版本适配流程

ZCode 升级后，旧补丁集一定失效：`out/` 下 chunk 文件名带内容哈希会变，锚点字符串也可能随代码位移。下面是标准流程。

## 0. 先判断影响面

```bash
npm run verify
```

输出会逐条列出每个目标的三种状态：

- `已应用` —— 标记串已在，无事可做
- `未应用（锚点就位）` —— 锚点还在，直接 `npm run apply`
- `锚点失配` / `目标文件不存在` —— 需要适配

## 1. 建立新版本补丁集

```bash
cp -r patches/3.11.2 patches/<新版本>
```

改 `patches/<新版本>/manifest.json`：`appVersion` / `buildCommitId` / `buildTime` / `electronBuilderVersion`。
`patches.json` 顶部也要同步 `appVersion`（脚本会校验两者一致）。

`build-*` 三个字段可以从安装包直接读：

```bash
npm run extract -- --file=out/metadata/build-meta.json
```

## 2. 重新定位 chunk 文件名

```bash
# 找主进程 schema 所在 chunk：搜索一个只在 schema 里出现的设置键
npm run extract -- --grep="messageStreamShowReasoning:" --window=30

# 找渲染层主包 / schema 包 / i18n 包
npm run extract -- --list=out/renderer/assets/styles-
npm run extract -- --list=out/renderer/assets/src-
```

`--list` 会列出 asar 内的真实路径，把 `patches.json` 里每个 `file` 改成新名字。

## 3. 重新定位锚点

本项目用到的锚点与搜索线索：

| 补丁 | 搜索线索 | 说明 |
|---|---|---|
| 设置 schema（全量） | `recentProjects:` | 形如 `recentProjects:<别名>.array(<别名>.string()).default([]),locale:`；3 个文件里 zod 别名分别是 `e` / `t` / `E(x())` |
| 设置 schema（局部 patch） | `recentProjects:` | 同上的 `.optional()` 变体 |
| 设置服务 hook | `function nx()` | 返回 `{settings, loading, error, update, refresh}`；确认别名是否仍是 `nx` |
| 项目行组件 | `WorkspaceSidebarItem` | 组件 displayName；行组件是它的内部实现 |
| 项目行显示名 | `i$(e.label,e.remoteTarget)` | 显示名计算；旁边的 `U=_wt(e)` 是 SSH 连接信息 |
| 显示名渲染点 | ``children:re}),`` | 带 `min-w-0 truncate` 的标签 span |
| 「更多」菜单同步项 | `canSyncSkills:se,canSyncMcp:se` | 菜单项数组，本项目在其后插入 |
| 渲染层入口脚本 | `./assets/index-` | `index.html` 里 type=module 的入口标签 |

搜索命令：

```bash
npm run extract -- --grep="i\$(e.label,e.remoteTarget)" --file=out/renderer/assets/styles-<新名>.js --window=160
```

`--regex` 可开启正则模式。确认锚点在文件内**唯一**（脚本会断言匹配次数，多于 1 次会直接报错）。

## 4. 验证到通过为止

```bash
npm run apply:dry
```

这一步会做全量重建（约 300MB 读写）并执行两道门禁：语法检查（`node --check`）+ 逐条自检（未改动文件逐字节比对、改动条目 integrity 核对）。**只有全绿才允许进入下一步。**

自检不通过时的常见原因：

- 锚点失配 → 报"锚点匹配 N 次，期望 M 次"，回到第 3 步
- 补丁后语法错误 → 报 `SyntaxError`。先确认**原始文件**是否能通过 `node --check`（能通过说明是补丁引入的）
- `替换目标未匹配到任何可替换条目` → 路径写错或该条目是 unpacked

定位建议：把可疑编辑单独抽出来做探针（`const probe=[<片段>]` 再过一次语法检查），比在 4MB 压缩文件里找列号快得多。

## 5. 应用

先**完全退出 ZCode（含托盘）**，然后：

```bash
npm run apply
```

脚本会备份原 `app.asar`、替换、写 `state/applied-<版本>.json`。

## 6. 运行验证

启动 ZCode 后：

1. 打开渲染层开发者工具，控制台应有 `[ZCode-Expand] 项目备注模块已注入 v...`
2. 控制台执行 `__ZC_EXPAND__.diag()`，应返回 `injected: true`
3. 侧边栏项目行「更多」菜单里应出现「编辑备注」
4. 写一条备注，重启应用确认仍显示（验证 `setting.json` 里出现了 `projectRemarks`）
5. 出问题就 `npm run rollback`

## 7. 出问题时

```bash
npm run rollback          # 恢复最近一次备份
npm run rollback --list   # 看有哪些备份
```

回滚同样要求 ZCode 已退出，且会在覆盖前再留一份当前状态。

也可以不改包直接临时关闭功能（在渲染层控制台执行）：

```js
localStorage.setItem('zcode-expand.remarks', JSON.stringify({ enabled: false }));
__ZC_EXPAND__.reload();
```

## 8. 提交

补丁集、源码、文档一起提交，commit 说明里写清适配到哪个 ZCode 版本与构建号。
